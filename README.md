# STM32 + VSCode: blink у `app.c` / `app.h`

Blink на **STM32F103C8 (Blue Pill)** із STM32Cube HAL (без Arduino Framework).
Бізнес-логіка винесена з `main.c` в окремий модуль `app.c` / `app.h`
з функціями `setup()` і `loop()` — за аналогією до Arduino Framework.

## Структура

| Файл | Роль |
|------|------|
| [src/main.c](src/main.c) | каркас: `HAL_Init()`, тактування 72 МГц, `SysTick_Handler`, виклик `setup()` і `loop()` |
| [src/app.c](src/app.c) | бізнес-логіка: налаштування PC13 і власне блимання |
| [include/app.h](include/app.h) | інтерфейс прикладного шару: два оголошення + include guard |

`main.c` не знає, *що саме* блимає і з яким періодом — лише викликає `setup()` один раз
і `loop()` у нескінченному циклі:

```c
setup();
while (1)
{
    loop();
}
```

## Уникнення циклічного/повторного включення

В [include/app.h](include/app.h) використано **include guard**:

```c
#ifndef APP_H
#define APP_H
/* ... */
#endif /* APP_H */
```

Під час першого включення `APP_H` ще не визначений — вміст файла потрапляє в одиницю
трансляції й макрос визначається. Будь-яке наступне включення (зокрема через ланцюжок
`a.h → b.h → a.h`) бачить визначений `APP_H` і пропускає весь вміст, тому повторних
оголошень і рекурсії препроцесора не виникає.
Однорядкова альтернатива — `#pragma once`: не входить у стандарт C, але підтримується
всіма актуальними компіляторами, включно з `arm-none-eabi-gcc`.

## Апаратна частина

| Сигнал | Пін | Примітка |
|--------|-----|----------|
| Світлодіод | PC13 | вбудований у Blue Pill, **active LOW** (світиться при лог. 0) |

Тактування: кварц HSE 8 МГц → PLL ×9 → SYSCLK 72 МГц, APB1 36 МГц, APB2 72 МГц.
Прошивка — через ST-Link (`upload_protocol = stlink`).

## Збірка та прошивка

```bash
pio run              # компіляція
pio run -t upload    # прошивка через ST-Link
```

Результат збірки: Flash 2 572 Б (3.9% з 64 КБ), RAM 44 Б (0.2% з 20 КБ).

## Результат

Світлодіод PC13 блимає з періодом 1 с (500 мс увімкнено / 500 мс вимкнено).
